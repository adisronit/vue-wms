Phase 29 — Multi-Tenant SaaS: Proposed Design

Phase 27 produced a six-document audit-and-design proposal for turning this single-tenant WMS into a multi-tenant SaaS product (docs/proposals/wms-saas/). Phase 28 implemented the first slice of that proposal — 8 new platform/tenant tables, structure only, zero application code. These four diagrams were generated with Archify directly from the Phase 27/28 proposal documents and the actual Phase 28 source, and they distinguish implemented fact from proposed design throughout. Nothing on this page implies that tenant isolation exists in the running application today — see the Known Gaps section on the portal home and each diagram's own status legend.

8 new tables shipped (Phase 28) 0 of ~30 business tables tenant-scoped 0 lines of tenant-enforcement code 6 migrations proposed (0043-0046)

Implemented vs Proposed — reading the diagrams

  • Implemented Solid connections/nodes with a plain tag, traced to a real file:line in backend/ or a real migration in backend/migrations/0041-0042.
  • Proposed Dashed connections/nodes tagged "PROPOSED", traced to docs/proposals/wms-saas/*.md — a reviewed draft, not yet built. No corresponding code or schema exists in the repository today.
  • Each diagram also carries its own in-page legend card (bottom of the diagram) restating this convention and the specific proposed/implemented boundary for that view.
