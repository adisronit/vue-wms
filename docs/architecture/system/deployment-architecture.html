Deployment ArchitectureImplemented

The UAT docker-compose.yml topology: five Compose services (frontend, backend, worker, migrate, rabbitmq) plus two named volumes, with SQL Server deliberately left outside the Docker network and reached via host.docker.internal.

Implementation Notes

  • This UAT compose file has no sqlserver service at all — SQL Server runs natively on the Windows host, a deliberate deviation from a fully-containerized pattern.
  • backend, worker, and migrate all connect out via DB_HOST=host.docker.internal, with extra_hosts: host.docker.internal:host-gateway added to each so the alias resolves reliably on any Docker Engine.
  • migrate is a one-shot container (target: migrate) that runs "wms-migrate up && wms-migrate seed" and exits; backend and worker both depends_on it with condition: service_completed_successfully.
  • export_files is the only volume shared between two services — it is mounted into both backend (serves the download endpoint) and worker (writes the generated CSV) at the same path.
  • Only two named volumes exist: rabbitmq_data and export_files. There is no sqlserver_data volume, consistent with SQL Server living outside Docker entirely.
