Frontend Component ArchitectureImplemented

The Vue 3 SPA's component layering: a single router guard, one shared layout, views grouped by domain, 17 per-domain service files, and a hand-rolled fetch wrapper that is the application's only path to the backend.

Implementation Notes

  • No Pinia or Vuex store exists anywhere in the project — confirmed absent from package.json. Session state lives entirely in localStorage under the key wms_auth.
  • router/index.js has exactly one global beforeEach guard: unauthenticated users are redirected to /login, and an already-authenticated user hitting /login is redirected to /dashboard.
  • services/api.js has no Axios dependency — its shared request() helper is a hand-rolled fetch wrapper that attaches the Authorization: Bearer header and acts as the de facto request/response interceptor.
  • A 401 response from any API call clears the stored session and force-navigates to /login via a callback the router registers through setUnauthorizedHandler.
  • views/inventory/NewStockAdjustmentView.vue is an orphan: it is an empty 0-line file, never imported by the router, and unreachable dead code. StockAdjustmentView.vue is the view actually routed.
