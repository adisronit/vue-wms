Implementation Notes

  • Migration-verified — all 36 tables trace to real CREATE TABLE/ALTER TABLE statements in backend/migrations/0001–0040; no model-only tables exist in this schema.
  • Identity reaches every other domain as creator/approver via users.created_by/approved_by (summarized in notes here rather than drawn as individual edges, since nearly every table has one) and scopes roles to warehouses via role_warehouse_access.
  • Inbound, Outbound, and Stock Control each mutate inventory through the same shared primitives (AddStock/RemoveStock/MoveStock/Reserve); one representative edge per domain is drawn (receipts, picking_tasks, stock_adjustments) rather than every mutating table.
  • picking_tasks is the Outbound fulfillment hub: a required 1:1 with shipments and a nullable 0..1:1 with orders, both enforced by UNIQUE foreign keys on the other table pointing back at picking_tasks.id.
  • stock_counts can generate stock_adjustments via the nullable source_stock_count_id column, added later by migration 0031.
  • Shipping performs no inventory mutation of its own and so has no direct edge into Inventory Core — see the Outbound ERD for the full picking/shipping/orders shape.
